# NOVA Trading Intelligence Neural Runtime

Status: isolated research runtime / not production inference.

## Scope

- Primary sequence model candidate: unidirectional PyTorch LSTM.
- Inputs: finalized, timezone-aware OHLCV bars for one explicit symbol/timeframe.
- Causal features: log returns, realized volatility, RSI, EMA gap, volume z-score, candle body and range.
- Outputs: bullish / bearish / sideways regime probabilities plus normalized predictive entropy.
- Artifact integrity: SHA-256 checked before loading.
- Safety: research candidate only; no broker client, order route, customer token, or live-trading capability.

## Run locally

Use Python 3.11 and install the CPU runtime:

```bash
python -m pip install numpy==2.1.3
python -m pip install torch==2.5.1 --index-url https://download.pytorch.org/whl/cpu
python -m unittest discover -s workers/trading_intelligence -p 'test_*.py' -v
```

Call `train_candidate(rows, symbol, timeframe)` with real, finalized OHLCV bars. The default `allow_session_gaps=False` policy requires strictly contiguous bars. For a broker feed with market-session closures, explicitly set `allow_session_gaps=True`: timeframe-aligned pauses up to 6 hours remain in-segment and are represented by the causal `log_elapsed_intervals` feature; closures from 24 hours through 4 days start a new segment and reset feature warm-up. Gaps between 6 and 24 hours, gaps over 4 days, non-timeframe-aligned gaps, duplicates, reversals and impossible OHLCV are quarantined. Sequence windows and forward labels cannot cross long-closure boundaries; no synthetic candles are inserted. This is a conservative candidate policy, not a substitute for a broker session calendar. Optional broker `spread` values are validated, preserved in the canonical dataset hash and summarized in the manifest as symbol points; spread is provenance/cost data, not an LSTM input feature. The gap policy and interval-gap manifest are included in candidate provenance, and shadow inference must use the same gap policy.

The function fits on the chronological training partition, uses the validation partition for early stopping, and reserves a purged final OOS partition without reading its labels. It returns a candidate artifact and a manifest marked `research_candidate` / `not_evaluated`.

Call `infer_research_candidate` only for offline/shadow research. It requires newer bars than the training snapshot and returns explicit `researchOnly=true` and all execution flags false. This is not wired to the customer-facing Dashboard or a hosted API.

## Promotion is intentionally impossible at this stage

No Final OOS report, walk-forward performance, transaction-cost evaluation, trade count, calibration approval or independent review is generated by this package. The candidate cannot be marked validated or promoted. A separate evaluation pipeline must be implemented and run against the real Exness Demo dataset before the existing frontend inference evidence contract can accept a production result.

Do not use synthetic fixtures in `test_neural_runtime.py` as performance evidence. They only test deterministic code paths and fail-closed boundaries.
