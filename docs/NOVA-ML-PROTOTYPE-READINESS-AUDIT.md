# NOVA ML Prototype Readiness Audit

Baseline inspected: `main` at `3105ad79990fa6596d1e210e7a645b0b0e12e5fa`  
Scope: XGBoost, LSTM and chart Vision prototypes found in the repository  
Status: prototypes are not approved for production or strategy fusion

## Findings

### XGBoost prototype — blocked

File: `workers/feature/supervised_xgboost_prototype.py`

- `funding` is generated with `numpy.random.uniform`; it is synthetic noise, not observed funding data. A trained model could learn randomness and the feature is not reproducible.
- The target is `close.shift(-5) > close`, but the final five labels are generated by pandas comparison against missing future values and become false rather than being excluded. This contaminates the tail of the training set.
- `model.score(X, y)` evaluates on the same rows used for fitting. It is in-sample accuracy, not validation or OOS evidence.
- There is no chronological split, purging/embargo, cost-aware strategy evaluation, calibration, artifact lineage or baseline comparison.
- The demo path uses synthetic random-walk prices and random volume; it is not evidence of market performance.

Disposition: do not import, train, or connect this prototype to Meta Decision. Replace it with a deterministic point-in-time feature builder, explicit future-return labels with invalid tail rows removed, chronological/purged walk-forward evaluation and OOS calibration.

### Chart Vision prototype — blocked

File: `workers/feature/cnn_vision_prototype.py`

- The forward pass masks random pixels but returns only pooled encoder features.
- The decoder is defined but never used; no reconstruction target, loss function, optimizer, training loop, checkpoint or evaluation is implemented.
- Random masking has no fixed seed or reproducible sample manifest.
- No causal chart renderer or image-to-market timestamp lineage is specified. A chart image could leak future candles or later annotations unless the renderer is timestamp-bounded.

Disposition: do not describe this as a trained Masked Autoencoder or a validated chart-understanding model. First define a causal chart-image dataset manifest, reproducible masking, decoder reconstruction objective, chronological splits and downstream OOS evaluation.

### LSTM — implementation not verified

Repository search on the inspected main revision found research documentation referencing PyTorch LSTM, but no concrete LSTM model implementation in the searched feature-worker paths. This is not proof that no implementation exists elsewhere in the repository; it is insufficient evidence to enable the LSTM plugin.

Disposition: locate and review any candidate implementation before reuse. Otherwise implement a minimal unidirectional sequence model with point-in-time inputs, fixed sequence boundaries, train-only normalization, chronological/purged validation and an explicit next-bar decision timestamp. Do not use bidirectional recurrence for live-causal inference unless its historical use is carefully constrained to data already available at the decision time.

### Deep Learning — model family is underspecified

"Deep Learning" is not a model architecture or acceptance criterion. It must be defined as a distinct model family (for example, a temporal convolutional network or compact Transformer) with a documented task, input schema, label horizon, parameter budget, deterministic seed and OOS evaluation. Avoid adding a second model that duplicates the LSTM's information without measurable incremental value.

## Gate before Meta Decision integration

1. Each model adapter is versioned and emits direction, bounded score, timestamp, model version, dataset SHA, feature schema and evaluation reference.
2. The backend—not the client—resolves and verifies calibration records and OOF prediction artifacts.
3. Model votes share the same decision timestamp, dataset snapshot and evaluation window.
4. Redundancy is measured from aligned OOF predictions, not from same-bar signal agreement alone.
5. Every model is compared with a simple baseline and ablation-tested. Keep a model only if it adds stable incremental value after costs across walk-forward folds.
6. Vision images are rendered strictly as-of the prediction timestamp; no future bars, labels, chart annotations or revised candles are allowed.
7. Freeze final OOS before model selection. No threshold changes after final OOS inspection.

## Decision

The new Meta Decision and Premium/Discount modules are research scaffolding only. Existing XGBoost and Vision prototypes are explicitly blocked from production fusion until corrected and re-evaluated. No trained-model performance claim is made.
